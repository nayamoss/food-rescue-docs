How it works

1

Organizer files a report

400 meals, main hall, 45 minutes. A short form on the dashboard, prefilled so it takes one click.

2

The app checks and confirms

Quantity, item, location and minutes are validated, then confirmed with one tap.

3

Incident goes live

Dashboard flips to urgent with a 45:00 countdown and 400 unclaimed.

4

Twilio calls every partner

"Food rescue. 400 meals at main hall. Press 1 to claim 100, press 2 to pass."

5

Partners press 1 to claim

Who claimed what shows on the dashboard, the unclaimed count drops.

6

Pickup is confirmed

A Mark picked up button on the dashboard. The rescued counter climbs toward 400.

7

Rescue complete

Celebration state, with an optional spoken announcement. If the clock runs out first, the rest is marked expired.

Decisions already made

Web app plus phone calls

No native app and no PWA. Partners install nothing. The organizer needs a browser.

Plain HTML and Express

No build step, less to break in 4 hours. React and Tailwind is possible if you prefer it.

Demo controls built in

Every step can be simulated from the dashboard, so the demo survives a failed call.

Food Rescue over Hamster HQ

Same loop technically. Food Rescue is the one that fits the brief, meal crisis included.

If something breaks

Form misbehaves

Use Create sample incident. It takes the same path.

Calls blocked

Use the simulate buttons. The feed tells the same story.

Repl restarts

State reloads from the saved file. Ping the URL before the demo.
